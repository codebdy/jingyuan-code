已根据完整 Figma 设计稿实现首页和 13 张内页（包括三个型号详情页）。现有 Astro 静态站、本地内容和原生 CSS/JavaScript 均保留，没有更换建站平台，没有发布。

交互包括：板块大标题和引导小标题依次淡入并变清晰、首页五条工艺内容随滚动依次柔和淡入、产品分类和关键词搜索、案例切换、图片轻缩放、一次数字递增、四大优势切换、设备和检验控件、图库和证书预览、原始证书图片下载、FAQ、产品栏目定位与吸附、询盘字段校验及草稿暂存。引导小标题延迟约 320ms，卡片二级标题直接显示；标题及工艺内容动效每页播放一次，首屏保留打字机效果。系统设置减少动态效果时停用非必要动效。

全站卡片统一为 1.2 秒柔和淡入、上移 16px，同组依次间隔约 0.26 秒。新增卡片使用 `data-reveal-card`，同组标记 `data-reveal-group`，复用 `src/styles/content-reveal.css` 的统一预设；卡片内标题不额外动画。内页导航默认白字、悬停橙色；首页仍为黑字、悬停白字，滚动后全站统一黑底白字、悬停橙色。产品中心六张卡片的文字区默认统一灰底、深色标题和说明，按钮黑底白字及白色图标，悬停时整块文字背景为黑色，名称橙色、说明白色，按钮橙底黑字及黑色图标；产品列表保留原有白色参数区，整卡悬停时仅联动加号按钮背景及产品型号变橙色。

三个型号复用原有详情画板，分别提供图片、型号和已知参数。点击首页、列表及相关产品的图片、型号、加号或 Read More，进入对应型号详情。原稿中尚未提供的技术数据继续保留待确认说明。新闻未提供详情画板和完整文章，入口展示原稿中的图片与摘要。分页以现有记录为准，没有对应记录的页码不可用。部分分类没有对应资料时显示明确的空状态，不复制记录凑页数。

修改时在 Codex 中说明页面和具体位置即可。AI 应先读取 `AGENTS.md`、`brief/`，再按 Figma 图层核对；不用手动编辑大段页面坐标。内页数据在 `src/data/design/`，共用渲染器为 `src/components/DesignNode.astro`，交互为 `src/scripts/site-interactions.ts`，原始素材为 `public/figma/`。首页继续使用原组件与 `src/pages/index.astro`。

制造与质量的两个设备分类共用同一套三张卡片布局，切换仅更换对应内容。说明、图片及文字在 `src/data/equipment-categories.ts` 中分开配置；耐火电缆设备素材待提供，目前保留同尺寸待上传内容位。

制造与质量的首屏、橙色区域电缆图片左上角均提供圆形视频按钮：播放图标固定居中，悬停时圆形背景提亮、边缘轻微波纹扩散。目前视频待提供，点击显示实际说明；后续提供视频文件后，在 `src/data/manufacturing-video.ts` 分别设置 `manufacturingVideoSrc` 与 `manufacturingOverviewVideoSrc` 的真实地址，即可在弹窗中使用原生播放器。

详情页的产品信息及技术参数可点击标题栏/加号折叠与展开。资料按钮默认黑色，询价按钮默认灰色，悬停均为橙色；询价跳转本页表单，资料缺失时继续显示实际说明。

正式询盘接入：在项目目录配置 `PUBLIC_INQUIRY_ENDPOINT` 后重新构建，接收端需处理表单字段并返回明确的 HTTP 状态。正式联调仍需确认接口、收件方式及响应协议；浏览器必填校验通过不等于邮件已送达。

以后需要重新启动预览时，在 Codex 中发送“启动京源电缆网站预览”，AI 会代为启动。需要发布时先提供正式域名和所选平台，确认后再上传；当前没有配置任何部署账号。

桌面以各画板的 1920px 宽度为基准等比呈现，800px 以下重排同一批内容。生产构建命令为 `pnpm build`。本轮验证记录见 `VERIFICATION.md`。

## 2026-11-25 全站交互维护

板块说明和独立图片的出现反馈、卡片悬停标记由 `src/scripts/motion-feedback.ts` 集中处理，与现有 `content-reveal.ts` 共用出现节奏；微交互样式位于 `src/styles/site-feedback.css`。不将大背景、表单或已有卡片内容重复包装成动效。质量检验说明的柔和开合由 `inspection-disclosure.ts` 处理；FAQ 由 `faq.ts` 处理，图标按最新要求为 14px。

新增切换可调用 `softenSwap`，会取消上一次同目标过渡，并尊重减少动态效果。维护时保留不同按钮的默认色例外，不用统一规则覆盖产品中心、新闻、选型指南、下载及询价等已确认样式。图库/资料/视频共用弹窗需要清理各自状态，不能把缺少的文件或证书伪造成可用内容。

全页检查脚本：`scripts/audit-all-pages.mjs`（14 页 × 电脑/手机，资源及截图）；`scripts/verify-card-styles.mjs`（正常/减少动态效果、滚动、布局与导航）；`scripts/verify-site-feedback.mjs`（折叠、图库键盘与状态、新闻整卡及内部链接）。截图和验证报告在本机临时目录，不作为网站素材。

证书统一样式以 `src/data/certificate-style.ts` 复用 about 原稿完整卡片，包含图片、日期、标题、说明。分类暂无正式资料时展示同款原稿示例版式，后续在 `src/data/certificate-categories.ts` 按分类填入实际图片、标题、有效期和说明；不要把示例日期或认证名称当成企业实际资质。

导航 Inquiry 由 `src/components/InquiryDialog.astro` 提供共用简约询价弹窗，样式在 `src/styles/inquiry-dialog.css`。字段校验、会话草稿和接收地址复用现有询盘处理；弹窗草稿使用独立前缀。产品详情自动带入当前型号，无 JavaScript 时入口回退到联系页。通过 `scripts/verify-inquiry-dialog.mjs` 检查全站、手机、关闭与键盘行为；实际收件仍需配置上述接收接口并联调。

首页首屏下方的真实视频为 `public/videos/home-braided-cable.mp4`（用户原片，1920×1080），对应首帧封面为 `home-braided-cable-poster.webp`。在 `src/pages/index.astro` 的 `.hero-photo` 位置引用，静音循环、进入视区播放、离开视区暂停，原生控件可手动操作；减少动态效果时由用户手动播放。

## GitHub 源码与后续更新

源码仓库为 https://github.com/codebdy/jingyuan-code，网站项目直接位于仓库根目录。克隆或下载后，在包含 package.json 的目录安装依赖，再执行 `pnpm dev` 进行本机预览、`pnpm build` 生成 dist。上传源码与网站部署分别处理；当前没有配置自动部署。

每次修改后先构建并检查本地预览，再提交并推送到 main。node_modules、dist、.astro、本地 .env 及日志不提交；空白的 .env.example 用于说明可选询盘接收配置。图片、动图、视频和已完成页面源码随仓库保存，无需依赖本机 Downloads 目录。
